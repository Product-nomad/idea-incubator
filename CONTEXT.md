# Project domain language

Single source of truth for the vocabulary this project uses. Every term in this file should mean exactly the same thing in the README, the bot's prompt strings, the YAML frontmatter, the code comments, and any external write-up. Aliases drift; this file picks one and enforces it.

If two docs disagree, this file wins. Fix the other place.

## Capture flow

| Term | Meaning | Don't say |
|---|---|---|
| **Idea** | A single captured concept, persisted as one Markdown file in the private ideas repo. The unit of work. | "Pitch", "concept", "note" — those are something else. |
| **Capture** | The act of running a `/new` flow to record a new idea. Always six questions, always ends with a Mom-Test critique. | "Submit", "create", "log". Use *capture*. |
| **Submission** | One execution of the `/new` flow. May or may not result in a saved idea (the user can `/cancel`). | — |
| **Submitter** | The Telegram user who ran `/new`. Recorded in frontmatter `by:`. | "Author", "owner". |

## The six questions

These are the questions the bot asks during `/new`, in order. The names below are the canonical IDs used in `bot.py`, `ASSESSMENT_PROMPT`, and the saved Markdown body. Don't rename without sweeping all four places.

| ID | Prompt to user | Frontmatter / body section |
|---|---|---|
| `title` | *"Give this idea a short working title."* | YAML `title:`, body `# {title}` heading |
| `niche` | *"Who specifically has this problem? Describe the niche as narrowly as you can (role, context, life-stage)."* | YAML `niche:` (truncated to 200 chars), body `## Niche` |
| `problem` | *"What problem are they facing? What's the main challenge right now?"* | body `## Problem` |
| `prior_attempts` | *"How have they tried to solve this before — with effort or money?"* | body `## Prior attempts (effort or money)` |
| `blockers` | *"What's prevented them from solving it so far?"* | body `## Blockers` |
| `magic_wand` | *"If they had a magic wand, how would they ideally solve this?"* | body `## Magic wand (ideal solution)` |

## Assessment

| Term | Meaning |
|---|---|
| **Critique** | The Markdown block Claude returns after the six answers, embedded in the saved file under `## Mom Test Critique`. Five sub-sections: Verdict, Evidence quality, What's missing, Recommended next step, Mom Test red flags. |
| **Verdict** | One of `Strong evidence` / `Mixed` / `Mostly hypothetical`. Recorded in YAML `verdict:` for downstream filtering. Three exact strings — don't add others without updating the dashboard. |
| **Tags** | 2–4 short lowercase hyphenated strings the LLM emits with the critique (e.g. `b2b`, `dev-tools`, `ai`). Recorded in YAML `tags:` as a list. Used for the auto-generated tag-cluster diagram. |

## Status lifecycle

These are the only allowed values of YAML `status:`. The `/status` command validates against this list; the bot rejects anything else.

| Value | Meaning | Typical next step |
|---|---|---|
| `inbox` | Just captured. No discovery work done yet. Default for every new idea. | Run 5–8 Discovery Calls with the named niche. |
| `discovery` | Actively running customer-discovery conversations. | Decide whether evidence supports a smoke test. |
| `smoke-test` | Built a landing page or a paid pre-order funnel; measuring demand. | Decide whether to commit to building. |
| `mvp` | Building the first version. | Ship to a small audience and measure use. |
| `killed` | Deliberately retired — either kicked out of scope (`purpose.md`) or proven not to work. | None. The killed file stays in the repo as a record. |

Use the values exactly. *Don't* introduce `paused`, `on-hold`, `parked`, `wip`, or other near-synonyms without amending this file and the `STATUSES` list in `bot.py`.

## Files in the captured idea

| Section | Source | Notes |
|---|---|---|
| YAML frontmatter | Auto-generated by `save_markdown` | `title`, `submitted` (ISO timestamp), `by`, `status`, `verdict`, `niche`, `tags`. |
| Body sections | Auto-generated from the six question answers + the Claude critique | `## Niche` through `## Magic wand` are direct user input; `## Mom Test Critique` is LLM output; `## Notes` is empty by default. |
| `## Notes` | Appended by `/note` command, one timestamped block per call | Newest at the bottom (chronological). Format: `### YYYY-MM-DD HH:MM` then the note text. |

## Repos

| Term | Meaning |
|---|---|
| **Bot source** | This repo — `Product-nomad/idea-incubator` (public). Holds `bot.py`, governance docs, `idea-bot.service.example`, `CONTEXT.md` (this file). No idea data. |
| **Ideas repo** | The separate private repo `Product-nomad/idea-incubator-ideas`. Holds the captured `.md` files at root and the auto-generated `README.md` index. Pointed at via the `IDEAS_DIR` env var. |
| **Index** | The auto-regenerated `README.md` at the root of the ideas repo. Shows status pie + tag-cluster graph + a table of all ideas. Regenerated on every `/new` and `/status`, not on `/note`. |

## Sub-processors

| Term | Meaning |
|---|---|
| **Telegram** | The chat surface. The bot is reachable as `@Incub8_bot`. The `python-telegram-bot` library handles the conversation. |
| **Claude** | The LLM that generates the Mom Test critique. Configured via `CLAUDE_MODEL` env var; defaults to `claude-opus-4-7`, currently overridden to `claude-haiku-4-5-20251001` for cost. |
| **GitHub** | Hosts both repos and runs the auto-push for captured ideas. Uses SSH auth as `Product-nomad`. |

## What this file is *not*

- Not a glossary of methodology terms ("Mom Test", "Discovery Call"). Those are explained in the README and the bot's prompt strings. They're acknowledged inspirations, not project-internal vocabulary.
- Not a status-of-the-project file. That's `STATE.md`.
- Not a decision log. That's `DECISIONS.md` (or `docs/adr/` once we cross the threshold per `~/WAYS_OF_WORKING.md` §9).
